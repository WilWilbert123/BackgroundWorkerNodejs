# Supabase to MSSQL Background Worker

This is an automated background worker built in Node.js. Its purpose is to continuously listen for new records (like Orders) in Supabase and seamlessly synchronize them down to a local or on-premise Microsoft SQL Server (MSSQL).

##  How it Works

1. **Real-time Listener**: Subscribes to Supabase using websockets (`postgres_changes`) to instantly detect new orders.
2. **Auto-Catchup Polling**: As a safety net, it checks every 10 minutes to grab anything that might have been missed due to network drops.
3. **Smart Insertion**: Safely inserts data into MSSQL inside a transaction, avoiding duplicates.
4. **Auto-Cleanup**: Once successfully committed to MSSQL, it updates the `is_saved = true` flag in Supabase so your Supabase database can automatically clean up old data.

## Setup & Configuration

### 1. Prerequisites
- [Node.js](https://nodejs.org/) installed on this machine.
- Access to your local/on-prem MSSQL Server.
- Supabase project URL and keys.

### 2. Environment Variables
Create a `.env` file in this directory and populate it with your credentials:

```env
SUPABASE_URL=your_supabase_url
SUPABASE_ANON_KEY=your_supabase_anon_key

MSSQL_USER=your_db_user
MSSQL_PASSWORD=your_db_password
MSSQL_DATABASE=your_database_name
MSSQL_SERVER=localhost\SQLEXPRESS
MSSQL_PORT=1433
```

### 3. Install Dependencies
Open a terminal in this folder and run:
```bash
npm install
```

---

## Running the Worker

### Option A: Run Manually (For Testing)
To see the logs and test if it's working:
```bash
node worker.js
```

### Option B: Run Silently in the Background
Double-click `Start_Background_Worker.vbs`. This will start the worker completely invisibly without leaving a command prompt window open.

### Stopping the Worker
Double-click `stop.bat`. This will read the `worker.pid` file generated by the worker and safely kill the background process.

## Setting Up Auto-Start (Windows)

If you want this worker to start automatically every time this Windows machine is rebooted or turned on:
1. Double-click `Make_It_Auto_Run_On_Startup.vbs`.
2. It will automatically create a shortcut in your Windows Startup folder pointing to the silent start script.

## Supabase Configuration (Optional Auto-Delete)

To keep your Supabase database lightweight and avoid storage costs, you can add a trigger in Supabase that instantly deletes the order once this worker flags it as `is_saved = true`.

Run this in your **Supabase SQL Editor**:

```sql
-- 1. Create the cleanup function
CREATE OR REPLACE FUNCTION auto_delete_saved_row()
RETURNS TRIGGER AS $$
BEGIN
  -- Automatically delete the row that was just marked as saved
  DELETE FROM "tblOrderHeader" WHERE "OrderCode" = NEW."OrderCode";
  RETURN NULL;
END;
$$ LANGUAGE plpgsql;

-- 2. Attach the trigger to your table
CREATE TRIGGER trg_auto_delete_saved
AFTER UPDATE OF is_saved ON "tblOrderHeader"
FOR EACH ROW
WHEN (NEW.is_saved = TRUE)
EXECUTE FUNCTION auto_delete_saved_row();
```
